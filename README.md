# Loan Default Prediction (Credit Risk)

Predicts whether a loan applicant will default, trained on real credit data.
Built for Bishal Rajdev Barik's resume for the **BNP Paribas Data Science
Intern (India CoE, Bengaluru)** application — every metric reported here comes
from actually running the code on the dataset below. No numbers are invented.

## Dataset

**German Credit (UCI ML Repository, Statlog)** — 1,000 loan applicants,
20 attributes, binary outcome (good credit / bad credit = default).
Source: https://archive.ics.uci.edu/ml/machine-learning-databases/statlog/german/german.data

**Why German Credit and not Home Credit:** the Home Credit Default Risk
dataset is distributed through Kaggle and requires Kaggle API credentials to
download. No Kaggle credentials are available in this environment (the Kaggle
API returns 403 without them), so the public UCI German Credit dataset — a
standard credit-risk benchmark — was used instead. **No Home Credit numbers
are claimed anywhere in this project.**

- 20 raw features (13 categorical, 7 numeric) → 61 after one-hot encoding
- 30% default rate (300 defaulters / 1,000 applicants)
- 0 missing values in the raw file (median/most-frequent imputation is still
  in the pipeline for robustness)

## What it does

1. **Cleans** the data and one-hot encodes the categorical features.
2. **Splits stratified 60% train / 20% validation / 20% test.** Validation is
   used for model selection and threshold tuning; the test set is evaluated
   exactly once, so the reported numbers are honest.
3. **Handles class imbalance** with class weights (`class_weight='balanced'`
   for Logistic Regression and Random Forest; `scale_pos_weight` for
   XGBoost). No SMOTE — with 1,000 rows, class weighting avoids
   synthetic-sample and leakage risks. (If SMOTE were used, it would be
   fitted on training folds only.)
4. **Trains and compares** Logistic Regression, Random Forest, and XGBoost on
   ROC-AUC, precision, recall, and the confusion matrix — not accuracy alone.
5. **Tunes the decision threshold** on the validation set by maximising the
   F2-score (recall weighted 2× precision): in lending, a missed defaulter
   costs far more than a false alarm, so recall is deliberately prioritised.
6. **Explains predictions** with SHAP (TreeExplainer) and ships a simple
   points-based **scorecard** derived from the logistic regression
   (`scorecard.csv`) — the kind of traceable, explainable output a bank's
   credit officers and regulators can actually use.

## How to run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python train.py        # downloads data from UCI, trains, writes metrics.json + RESULTS.md
streamlit run app.py   # interactive demo: enter an applicant, get a risk flag + SHAP reasons
```

## Honest limitations

- 1,000 rows is small; confidence intervals on the test set (200 rows) are
  wide, and German Credit is from 1994 — applicant behaviour and products
  have changed since. The numbers are real, but they describe this dataset,
  not a modern loan book.
- The scorecard is a simplified points version of the logistic regression,
  not a full Weight-of-Evidence / Information-Value scorecard.
- This is a demo, not a lending decision system.
